# Ads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any app can show a compliant AdMob banner on Android and iOS, by config plus one DSL line.
The foundation enforces the house rules: consent first, no ads on first launch, none during an
ad-free window, banners only, never on forms or settings. Apps grant ad-free time from their own
shared code. Showcase proves it in Debug, with Google's test IDs.

**Architecture:** The ads work mirrors the Firebase work merged in #44.
- **`:core:ads:shared` (KMP):** the rules (`AdGate`), the persisted launch counter and ad-free
  window, tracking sequencing, and `AdsController.bannerState(placement)`.
- **Android:**
  - `:core:ads` is the API module: the `ads { }` DSL, the `AdBanner` composable (it collapses
    without an SDK), and the shell's "under a tab" slot;
  - `:core:ads:google` is the SDK module (Google Mobile Ads), contributed through
    `ServiceLoader` only into the build types that enable ads.
- **iOS:** a `WhitelabelAds` Swift target (GoogleMobileAds SPM) with a SwiftUI `AdBanner`, an
  `AdsService: AppService`, and an ATT `TrackingPort`.
- **Consent:** reuses `:core:consent:*`, so an app with ads gathers consent even without Firebase.

**Tech Stack:**
- Kotlin KMP, Koin, kotlinx.serialization, `JsonStore`, `kotlin.time.Clock`;
- Google Mobile Ads (Android: `com.google.android.gms:play-services-ads`; iOS: SPM
  `swift-package-manager-google-mobile-ads`);
- Compose, SwiftUI, XcodeGen.

**Spec:** `docs/superpowers/specs/2026-11-12-firebase-and-ads-kmp-design.md`, section 5 (with 0, 1 and
3a), plus the amendments in sections 3a and 4.1 (AdMob app IDs, owner, 2026-11-12). Parent:
`2026-11-10-standalone-app-support-design.md` section 6.

## Global Constraints

**Config:**
- `ads.enabled` accepts exactly `false` (default), `true` or `debug`.
- With `true`, both app IDs and every declared placement's unit ID must be present and well formed
  for each platform. App IDs match `^ca-app-pub-\d{16}~\d{10}$`; unit IDs match
  `^ca-app-pub-\d{16}/\d{10}$`.

**Test IDs:** Debug always uses Google's public test IDs, whatever the properties say:
- Android app `ca-app-pub-3940256099942544~3347511713`, adaptive banner
  `ca-app-pub-3940256099942544/9214589741`;
- iOS app `ca-app-pub-3940256099942544~1458002511`, adaptive banner
  `ca-app-pub-3940256099942544/2435281174`.

  Exception: when a real app ID is present, Debug keeps it in the manifest or plist so UMP finds the
  app's consent message. Only the banner units are swapped for test units.

**House rules,** enforced in `AdGate` and not by apps:
- no ad request before consent is `Resolved(canRequestAds = true)`;
- no ads on launch 1;
- no ads during an active ad-free window;
- an undeclared placement never shows;
- banners only.

**Where banners may go:**
- The shell refuses a placement under the Settings tab, and the auth gate never shows a banner.
- Shared features never depend on ads.

**iOS tracking (ATT):**
- Asked only when `ads.ios.requestTracking=true`, the first time a banner would load, after consent
  is resolved; never at startup, and never on launch 1.
- `ads.ios.trackingMessage` is required when it's on.
- The foundation never forces non-personalized requests.

**What apps without ads get:** nothing. No SDK, no Gradle change, no Info.plist keys beyond the
existing empty placeholders, no Swift package.

**Release:**
- Android release APKs contain no `com/google/android/gms/ads` (nor the token
  `MobileAdsInitProvider`) unless `ads.enabled=true`; `scripts/verify-apps.sh release` checks this.
- On iOS, Release may link the package (SPM can't drop it per configuration) but never starts it
  when ads are off for Release.

**The banner** is labelled "Ad" ("Annonce" in fr), collapses to zero height when hidden, loading or
failed, and never shows an error.

**Privacy row:** the existing `PrivacyChoicesRow` (#44) serves ads too; there's no separate
`AdPrivacyRow`.

**Process:**
- UI tests are paused by the owner. Don't write or run XCUITests or Android instrumented tests; unit
  tests use TDD.
- Git rules as in `CLAUDE.md`. Use the simulator "iPhone 18 Pro Max" and an emulator no other
  session uses.

## Review Focus

1. **The process restarts mid-launch** (the activity is recreated). Expected: the launch counter
   counts process starts, not activity creations, so ads don't appear early (Task 1).
2. **Ad-free `extend` while a window is active, or after it expired.** Expected: it stacks onto the
   remaining time, or starts from now; it never shortens the window (Task 1).
3. **Consent changes from Resolved to Failed during a launch** (privacy options). Expected: the banner
   hides from the next state on, and no new request is made (Task 2).
4. **Two banners for the same placement at once** (rotation, or two screens). Expected: each observes
   the same state, and tracking is requested at most once per launch (Task 2).
5. **`ads.enabled=debug` with no unit IDs at all.** Expected: the build passes and Debug uses test
   units; Release has no ads and no SDK (Tasks 3 and 4).

### Task 1: The rules, the launch counter and the ad-free window (`:core:ads:shared`)

**Files:**
- Create: `core/ads/shared/build.gradle.kts` (`whitelabel.kmp.library`, `whitelabel.koin`; commonMain
  `api(project(":core:consent:shared"))`, `implementation(project(":core:datastore"))`,
  `api(libs.kotlinx.datetime)`)
- Modify: `gradle/foundation.settings.gradle.kts` (add `":core:ads:shared"`)
- Create in `core/ads/shared/src/commonMain/kotlin/com/whitelabel/core/ads/`: `AdGate.kt`,
  `LaunchCounter.kt`, `AdFree.kt`
- Test: `core/ads/shared/src/commonTest/kotlin/com/whitelabel/core/ads/`: `AdGateTest.kt`,
  `LaunchCounterTest.kt`, `AdFreeTest.kt`

**Interfaces:**
- Produces:
  ```kotlin
  sealed interface AdDecision { data object Show : AdDecision; data class Hide(val reason: HideReason) : AdDecision }
  enum class HideReason { ADS_OFF, CONSENT_PENDING, CONSENT_FAILED, CONSENT_NO_ADS, FIRST_LAUNCH, AD_FREE, UNDECLARED }
  fun adGate(adsEnabled: Boolean, placementDeclared: Boolean, consent: ConsentState,
             launchNumber: Int, adFreeUntil: Instant?, now: Instant): AdDecision
  class LaunchCounter(store: JsonStore<...>, scope: CoroutineScope) { suspend fun countThisLaunch(): Int; val launchNumber: StateFlow<Int> }
  sealed interface AdFreeState { data object Inactive : AdFreeState; data class Active(val until: Instant) : AdFreeState }
  class AdFree(store: JsonStore<...>, clock: Clock, scope: CoroutineScope) {
      val state: StateFlow<AdFreeState>
      suspend fun grantUntil(until: Instant)
      suspend fun extend(by: Duration)
  }
  ```
- `adGate` checks the rules in this order, so the reason is deterministic: ads off → undeclared →
  consent (`Unknown` → CONSENT_PENDING; `Failed` → CONSENT_FAILED;
  `Resolved(canRequestAds=false)` → CONSENT_NO_ADS) → first launch (`launchNumber <= 1`) → ad-free
  (`adFreeUntil > now`) → Show.
- **`LaunchCounter`:** `countThisLaunch()` increments the persisted count once per process. A second
  call in the same process returns the same number.
- **`AdFree`:** `extend` adds to `max(now, currentUntil)`. `grantUntil` never shortens an active
  window (it keeps the later instant). `state` becomes `Inactive` once `now >= until`, re-evaluated on
  each read/collect with the injected clock.

  - `LaunchCounterTest`:

    - `` `counting twice in one process doesn't advance` `` (Review Focus 1).

### Task 2: Banner state and tracking sequencing (`:core:ads:shared`)

**Files:**
- Create in `core/ads/shared/src/commonMain/kotlin/com/whitelabel/core/ads/`: `TrackingPort.kt`,
  `AdsController.kt`, `AdsKoin.kt`
- Test: `AdsControllerTest.kt`

**Interfaces:**
- Consumes: Task 1, and `Consent` (`:core:consent:shared`).
- Produces:
  ```kotlin
  interface TrackingPort { fun requestIfNeeded(onDone: () -> Unit) }   // callback: Swift implements it
  object NoTracking : TrackingPort                                     // Android, and iOS with the switch off
  sealed interface BannerState { data class Hidden(val reason: HideReason) : BannerState; data class Ready(val unitId: String) : BannerState }
  class AdsController(enabled: Boolean, units: Map<String, String>, consent: Consent, launches: LaunchCounter,
                      adFree: AdFree, tracking: TrackingPort, clock: Clock, scope: CoroutineScope) {
      fun bannerState(placement: String): StateFlow<BannerState>
  }
  fun adsModule(enabled: Boolean, units: Map<String, String>): Module   // binds AdsController, AdFree, LaunchCounter
  ```
- **`bannerState`** combines consent, launch number and ad-free state through `adGate`.
- **Tracking:** on the first transition to Show in a launch, it calls `tracking.requestIfNeeded`
  once per launch (shared across placements), and emits `Ready` only after `onDone`.
- `units` maps a placement to its unit ID, already resolved per build type by the build (test units
  in Debug).
- `AdFree` is resolvable by apps from Koin, so Munch's rewards call it.

**Interfaces:**

  data class AdsSetup(val dependencyConfiguration: String?, val modeFor: Map<String, String>,      // "on" | "off"

  fun adsSetup(mode: ServiceMode, appId: String?, units: Map<String, String>, platform: Platform, label: String): AdsSetup

- **Rules:**
  - `OFF` → all off.
  - `ON` → both build types on; requires the app ID and at least the declared units (placements
    are known only from the DSL at runtime, so the build checks that every property unit is well

- **Android dependency:** `:core:ads:google` per `dependencyConfiguration`, and `:core:ads` +
